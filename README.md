# message-archive-pipeline

把多个群里的消息整理成「每日简报」的自动化管道：**去重 → 规则过滤 → 关键词分类 → 落库 → 生成日报**。

输入是标准 OneBot 事件格式（一行一条 JSON），所以可以接任何兼容来源；这个仓库只包含处理与推送层，采集层不在里面。

## 为什么做

群太多、通知太密，真正要紧的事（开会、DDL、需要确认的事项）很容易被刷过去。
这个管道的目标很简单：把噪音丢掉，把要紧的挑出来，每天生成一份人可以直接看的简报。

## 快速开始

```bash
python3 pipeline.py data/events.jsonl
```

输出：

- 终端：每一步的进度，以及每条被跳过的消息和原因
- `archive.db`：SQLite 归档
- `日报-YYYYMMDD.txt`：当天重要消息

示例输出：

```text
[1/4] 读取事件：data/events.jsonl
      共 12 条
[2/4] 去重
      去掉重复 1 条，剩 11 条
[3/4] 过滤规则
      跳过 1003：群名包含「福利」
      跳过 1005：非文本消息
      跳过 1008：群名包含「茶友」
      跳过 1010：发送者包含「助手」
      保留 7 条
[4/4] 入库 + 生成日报
      重要消息 6 条 -> 日报-20261020.txt
```

## 四个处理环节

| 环节 | 做法 |
|---|---|
| 去重 | 按 `message_id` + 内容哈希，重复推送只留一次 |
| 过滤 | 规则文件里配置要忽略的群名、发送者、非文本消息 |
| 分类 | 关键词命中判断「是否需要注意」 |
| 归档 | 落 SQLite，再生成 Markdown/TXT 日报 |

规则全部外置在 `filter-rules.json`，改规则不用改代码。

## 项目结构

```
pipeline.py          主流程：读取 → 去重 → 过滤 → 入库 → 日报
filter-rules.json    规则：忽略的群/发送者、关键词
data/events.jsonl    示例输入（假数据）
```

## 数据说明

仓库里的 `data/events.jsonl` 全部是编造的假数据，不包含任何真实聊天内容。

## 边界与后续

- 采集层直接对接本机客户端的消息同步（只处理自己的账号、自己的数据），不在本仓库
- 只依赖 Python 标准库，不需要装任何包
- 可扩展方向：换成语义分类（把 `classify()` 换成模型调用）、加 Web 面板、支持更多平台的事件格式
